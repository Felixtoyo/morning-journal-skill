# 大富晨间日记

[English README](README.md) · [Skill 执行规范](SKILL.md)

以佐藤传《晨间日记的奇迹》的九宫格理念为核心，用一问一答整理目标、感恩、行动和生活。支持同月同日历史回顾、复用已提供的健康数据，以及可选的 Notion 晨间日记保存。

这是受该书启发、按本项目指定顺序实现的九宫格晨间日记实践，不宣称逐字复刻原书模板。

## 固定九宫格

从左到右、从上到下，顺序固定：

| ① 今天的梦想/长期目标 | ② 开心的事、值得感恩的事 | ③ 今天优先完成的3件最重要的事 |
| --- | --- | --- |
| ④ 健康状态 | ⑤ 金钱相关 | ⑥ 人际 |
| ⑦ 学习与输入 | ⑧ 烦恼/卡点/改善 | ⑨ 今日一句自我鼓励 |

一次只问一个问题，等你回答后再继续。已知内容直接填入，不机械重复提问；一条回答涉及多个格子，也会分别复用。优先事项可以少于三件，不强行凑数。

你回答“无/没有”就留空，简短回答也可以，不脑补、不编造、不评判、不深挖隐私。说“停”立即停止，不继续提问或自动保存。只有你主动要求，才会在九宫格之外加上“昨日复盘”，默认关闭。

最终日记附上本实践的核心理念：

> 写晨间日记不是记录流水账，而是把潜意识的想法显化，对齐自己的目标。

## 同月同日历史回顾 / On This Day

开始访谈前，先在你**已经授权读取的晨间日记历史存档**中查询往年同月同日记录。

- 查到并读取了记录：简短展示真实日期和内容摘要；只有上一年的记录才称“去年的今天”，更早记录标明年份。
- 查询完整成功但无结果：直接进入访谈，无需宣布没有历史。
- 查询失败、未完成、无权限或未配置来源：跳过；必要时说明“这次未能读取历史日记”，绝不把失败说成“没有历史记录”。

只查询授权的日记存档，不搜索无关记录。以日记日期为准，不拿创建时间冒充日记日期；2 月 29 日只匹配往年的 2 月 29 日。没有历史来源也能正常写日记。

## 复用健康数据与当地日期

使用你的当地日期和时区。如果你已提供睡眠、体重、身体感受或健康截图中的可靠数据，就直接复用，不重复询问。保留日期、单位、已知测量时间和来源，区分客观指标与主观感受，不把旧数据当成今天的数据，也不推断缺失数值。

本 Skill 用于日常反思，不提供医学诊断或治疗。

## 使用方法

下载仓库，把 `SKILL.md` 和 `reference/` 一起提供给支持 Skill 的助手。若宿主支持本地发现，将文件放在其支持的技能目录中名为 `morning-journal` 的文件夹下。安装路径因应用而异；仅打开 GitHub 仓库不会自动安装或激活。

你可以这样开始：

> 开始今天的大富晨间日记，一次只问一个问题，复用我已经上传的睡眠和体重，先不存 Notion。

也可以直接整理：

> 请把我上面的笔记整理成大富晨间日记，缺失的格子留空，不用再访谈。

需要昨日复盘时：

> 今天的大富晨间日记加上昨日复盘。

## 可选 Notion 保存

写日记和读取历史，都不自动授权写入 Notion。只有你要求保存，或已有适用的明确长期授权，才会执行外部写入。

1. 连接宿主支持的 Notion 集成，授权你选定的数据库或页面。
2. 助手读取实际字段结构，按你当地的日记日期查询当天是否已有日记。
3. 已有一篇就继续或更新该篇，保留无关内容；有多篇时先确认更新对象，不擅自合并或删除。
4. 只有成功确认当天不存在日记，才新建；查询失败就停止保存并保留聊天草稿。
5. 写入后重新读取，验证目标、日期、标题和九宫格正文，再返回已验证的页面链接。

写入超时或结果不明确时，先重新查询同一天再决定后续操作，不能盲目重试创建。回读失败会明确说明“尚未验证”，不虚假宣称保存成功。没有 Notion 也可完整使用聊天版。

## 隐私与能力边界

仓库不包含凭证、私人数据库 ID 或真实健康与日记记录，请把个人配置留在公开仓库之外。保存前留意发送到 Notion 的内容。本 Skill 本身没有健康 API、定时任务或自动同步能力；查重依赖查询成功，不是数据库原子唯一约束，应避免同一天并发保存。
